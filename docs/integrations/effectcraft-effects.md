# Native EffectCraft effects in Ferrocut

Verified 2026-10-08 against `storytold/effectcraft` revision
`6943872cf65b3da1275f1e0f808b60b2e51d84dc`. Ferrocut invokes the actual
vendored Rust CPU render functions through its ordinary `VideoEffect` stack.
This is a native library integration; no browser or external EffectCraft
application runs during these renders.

The pinned registry has **306 entries: 170 connected and 136 explicitly
unsupported**. The complete index below records every entry, including host
dependencies and known limits. An unsupported entry does not register a video
effect and fails if requested. These counts describe executable upstream
algorithms; they do not establish Adobe parity or production finish.

## Agent interface

Discover connected and unsupported effects with `ferrocut effects --query blur`.
Request `--details` on a narrow query for typed parameters, defaults, ranges,
choices and limitations. Pagination uses `--offset` and `--limit`.
The underlying engine APIs are
`ferrocut_engine::fx::effectcraft::{all, catalog, render_cpu}`; the complete
machine-readable catalog comes from `catalog()` and is the source of the index
below. `all()` returns only connected `Arc<dyn VideoEffect>` implementations.

Use the stable upstream `ec.*` identifier as `type`. Raw upstream parameter
identifiers, including slash-separated group names, remain JSON keys:

```json
{
  "type": "ec.color.exposure",
  "id": "grade",
  "master/exposure": {
    "keyframes": [{"t": 0, "v": 0}, {"t": 1, "v": 2}]
  },
  "bypassLinearLight": true
}
```

Effects use the existing ordered clip, track and adjustment stacks, generic
`add_video_effect`, `set_video_effect_param`, `move_video_effect` and
`remove_video_effect` operations. Numeric scalars, vector components and color
components accept Ferrocut integers, rational strings, keyframes and sandboxed
expressions. Use `"0.5"` or `"1/2"` for fractional timeline values. Popup values
are exact documented string labels; booleans and popup/string controls are fixed,
not animated. Bounds are checked at authoring and again on sampled frames.

Upstream `Point` parameters are **normalized canvas fractions**, so
`"center": ["0.25", "0.75"]` means one quarter of the canvas width and three
quarters of its height. The adapter expands them using the actual canvas size.
Pixel sliders retain pixel units; angle controls retain degrees. Other units
come from the declared metadata and source-specific mappings. An entry marked
`upstream units` retains the source control's numeric scale; consult its linked
renderer before assuming pixel or percentage semantics. Point3 controls retain
upstream coordinates. Color controls are straight linear ACEScg RGBA in [0,1],
with alpha defaulting to 1. `_seed` is an explicitly exposed animatable integer
control (rounded, 0..1,000,000,000), default 0; instance labels do not seed pixels.

Curves exposes five fixed strings, `rgb`, `red`, `green`, `blue`, `alpha`, with
`x,y` control points separated by whitespace/semicolons. For example,
`"rgb": "0,0 0.5,0.75 1,1"`. Each nonempty curve has 2..128 finite points in
[-16,16] and distinct x coordinates. The hidden upstream editor channel selector
is omitted because the five channel curves determine rendering. Glow's
`arbitraryMap` holds up to three such curves separated by `|`. PS Arbitrary Map's
`map` is a fixed comma/space-separated list of 2..1024 finite samples in [0,255],
with the upstream rule choosing normalized or byte-scaled samples. Strings are
bounded to 4096 UTF-8 bytes; malformed nonempty controls fail explicitly.

## Color, alpha, windows and timing

The bridge requires and returns premultiplied linear ACEScg. It normalizes source
overscan and sparse storage onto a transparent full-canvas buffer, preserves
upstream offset/padding, and extracts the requested absolute pixel region.
Input pixel aspect metadata survives. Points and bounds are calculated from the
actual canvas; no fixed output resolution or hidden font/asset lookup is used.

Pixels cross the bridge as 32-bit float RGBA and return as Ferrocut half floats.
The bridge does not quantize to 8-bit or clip RGB to [0,1]. Finite negative and
HDR input are accepted; each upstream effect retains its own clipping, transfer
function and quantization behavior. In particular, the Exposure example enables
`bypassLinearLight` to get direct linear exposure multiplication. Legacy upstream
algorithms that apply their own sRGB conversions retain those algorithms; setting
the working-space tag is not a claim that every legacy effect is physically
linear or Adobe-identical.

Input must be finite and alpha must be [0,1]. Transparent RGB is canonicalized to
zero. Output alpha is clamped to [0,1] and RGB rescaled with it to retain the
straight color; nonpositive alpha becomes transparent black. RGB is limited only
to the finite half-float range ±65504. Nonfinite upstream output and upstream
panics become permanent frame errors, never a successful inert fallback.

Numeric controls sample `req.param_time`: clip-local seconds for clips,
composition seconds for track/adjustment effects. Intrinsic procedural rendering
uses `req.effect_time`, which includes the effect's `clock_offset` maintained by
split/in-trim operations. Source speed/remapping does not silently turn clip
effect controls into source-clock controls. Upstream `comp_time` is the real
composition time; upstream frame rate is the timeline output rate (standalone
stacks default 30 and support `with_frame_rate`).

Cache keys include sampled controls, working space, pinned adapter version,
output rate and the effective intrinsic clock where needed. The adapter also
declares CC Ripple Pulse intrinsically time-dependent because its moving pulse
at nondefault levels is missing from the pinned upstream declaration. A
split/trim retains Noise's phase and effective cache identity.

Transform supports its sharp spatial transform. `shutterAngle` must be zero;
temporal shutter rendering needs a host that can sample parameters at other
times. The composition shutter service is not connected. CC Composite retains
the upstream behavior of compositing the image entering that effect with itself;
it cannot recover the original pre-stack image. These limitations are also in
the catalog.

## Resource and worker limits

This initial adapter executes upstream **CPU** implementations. GPU frames are
flushed, read back, processed and uploaded again. Adjacent native GPU effects
therefore incur transfer/submission costs. Correctness is tested on actual GPU
workers; real-time or UHD throughput has not been benchmarked and is not claimed.

Preflight limits are 8,388,608 canvas pixels, 16,777,216 pixels per normalized,
padded/internal or requested image, an 8192 canvas axis, and 256 pixels of padding.
Storage coordinates, finite parameters, clock magnitude, frame rate (0,1000],
output texture dimensions, filter kernels and procedural samples are bounded.
Spatial kernel/count parameter domains are intentionally narrower than some
upstream slider ranges. Dynamic image growth for pinning, slant, warps,
magnification, optics and radial shadows is predicted before upstream allocation.
The most expensive neighbourhood/noise/cell/lightning work also has a preflight
sampling budget. Some large canvases or nondefault combinations fail with a
specific instruction to reduce resolution, overscan or complexity.

A conservative scratch-image estimate must fit 1 GiB per worker. This is a
preflight estimate for adapter/upstream CPU storage, **not** an allocator-enforced
process RSS or total concurrent-worker budget. Upstream algorithms can retain
multiple buffers and Rayon channel/row scratch. GPU readback is separately size
checked before allocating its CPU copy. The renderer still needs an appropriate
worker count and machine memory budget.

Cancellation is checked before/after upstream execution and on every adapter
copy row. The pinned CPU render functions have no cancellation callback, so a
running monolithic upstream call cannot be interrupted cooperatively. Workload
caps bound admitted requests, but no strict wall-clock cancellation guarantee is
claimed. Procedural simulations, tracking/model analysis, unrestricted output
resizing, fonts, files/OCIO/LUTs, audio and multi-layer/temporal services remain
outside this adapter.

## Validation

`cargo test -p ferrocut-engine --offline --test effectcraft -- --nocapture`
executes 17 tests. Every connected effect renders both its defaults and a typed
nondefault control against a separate direct call to the pinned upstream library.
An independent exposure multiplication check verifies negative/HDR values and
premultiplied alpha. Other cases cover fixed enums and malformed curves, two
canvas resolutions and normalized points, sparse/negative windows, padded bounds,
host rejection, nonfinite pixels/parameters, allocation/work limits, cancellation,
seeds, fractional defaults, animation, expression baking, edit operations,
retiming, split/in-trim phase and cache changes. Extreme clock arithmetic,
decimal offsets, static-effect cache reuse and warm-cache invalid requests have
explicit regression checks; invalid split/trim batches preserve the original.

Actual readback/upload and graph rendering passed on NVIDIA GeForce RTX 5090
Laptop GPU (Vulkan, discrete) and llvmpipe (Vulkan, CPU), including recreated
worker state. The existing effects, expression and source-expression suites also
passed (37 focused tests total). The final 37-test run also executed NVIDIA and
llvmpipe readback/upload, with its [command log](artifacts/gpu-effects.log) retained.
The reference proves faithful library execution,
not independent artistic/Adobe equivalence for all algorithms or all parameter
combinations. Large-resolution/performance, all popup permutations and complete
visual-quality review remain unverified.
