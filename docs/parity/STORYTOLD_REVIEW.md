## What this means for Ferrocut

**These are substantial component and engine candidates. Evaluate them before implementing equivalent missing capabilities from scratch.** Both have native project models, rendering and agent interfaces; they are more relevant than a collection of HTML templates. There is already code connecting their editing and compositing models. A wholesale replacement of Ferrocut is a separate decision that needs measured evidence: none of the upstream runtime, performance or visual-parity claims was reproduced in this review.

The strongest near-term candidates are interchange, broadcast-caption formats, color/LUT helpers and numeric scopes. EffectCraft's path operators, tracking and advanced typography deserve targeted experiments. Replacing Ferrocut's editor, render graph, text renderer or expression engine would involve substantially more model, time, color, asset and cache integration.

On the inspected feature breadth, these repositories appear further along toward familiar Adobe workflows than the Ferrocut features we have demonstrated: examples include FilmCraft's AAF/OMF pipeline and EffectCraft's path text, rich typography and lit 3D renderer. That is useful evidence of broader coverage, **not evidence that their finished videos, reliability or performance are better than Ferrocut's**. The comparison still needs the same demanding projects rendered and revised through each engine.

EffectCraft's `Renderer` uses its project/evaluation context, footage and an optional `Accelerator`. An isolated renderer adapter is more reviewable than replacing shared primitives immediately. |

## Important limits and conflicting evidence

- **FilmCraft:** its roadmap separates feature presence from readiness and says approximations count as present. It documents missing plugin hosting, camera-media uncertainty, CPU-heavy render/effect paths and platform gaps. The same document contains stale delivery/HW statements next to newer hardware exceptions; qualify HEVC export by platform/provider rather than stating universal support or absence. [Pinned roadmap](https://github.com/storytold/filmcraft/blob/5231852443363f001c3f6b396dd9b1e6461ae2be/ROADMAP.md)
- **Interchange losses are material:** FilmCraft documents uncarried graphics/adjustment layers and AAF/OMF limits including retiming and synthetic media. Round trips within its own model do not prove Avid/Premiere/Resolve acceptance. [Interchange scope and test descriptions](https://github.com/storytold/filmcraft/blob/5231852443363f001c3f6b396dd9b1e6461ae2be/crates/interchange/README.md)
- **EffectCraft:** its gaps assessment, updated through October 8, explicitly says `.aep`/`.aepx` cannot be opened and Adobe plugins cannot run. It reports uneven platform reliability, untested large real projects/camera formats, and largely unmeasured behavior. Its own feature scorecard has stale/inconsistent rows; do not reuse its headline percentages as a completion metric. [Gaps assessment](https://github.com/storytold/effectcraft/blob/6943872cf65b3da1275f1e0f808b60b2e51d84dc/docs/gaps.md)
- **Some fidelity evidence does exist:** EffectCraft publishes eight scalar Rotation/ease cases, 168 samples against AE 26.3x87 through AEsync, dated October 5. This is narrow temporal-interpolation evidence, not rendered-frame, effect, spatial animation or whole-application parity. This review read the harness report but did not rerun it. [Measurement and remaining scope](https://github.com/storytold/effectcraft/blob/6943872cf65b3da1275f1e0f808b60b2e51d84dc/docs/fidelity/README.md)
- **GPU claims require feature-level checks:** EffectCraft documents a CPU reference, GPU acceleration and CPU fallback, including presentation-device recovery boundaries. Its architecture table still contains an older effect count while later sections describe newer coverage. Verify an individual path and target hardware rather than assigning all features the GPU label. [Rendering architecture](https://github.com/storytold/effectcraft/blob/6943872cf65b3da1275f1e0f808b60b2e51d84dc/docs/architecture.md)

## License and distribution boundary

Both inspected manifests declare `MIT OR Apache-2.0`; both repositories include MIT/Apache license files and notices. MIT source reuse requires preserving its copyright/permission notice; Apache use requires checking its applicable notice/attribution terms. This is a source check, not a legal clearance of every dependency, asset or codec. [FilmCraft MIT license](https://github.com/storytold/filmcraft/blob/5231852443363f001c3f6b396dd9b1e6461ae2be/LICENSE-MIT), [EffectCraft MIT license](https://github.com/storytold/effectcraft/blob/6943872cf65b3da1275f1e0f808b60b2e51d84dc/LICENSE-MIT), [FilmCraft Apache license](https://github.com/storytold/filmcraft/blob/5231852443363f001c3f6b396dd9b1e6461ae2be/LICENSE-APACHE), [EffectCraft Apache license](https://github.com/storytold/effectcraft/blob/6943872cf65b3da1275f1e0f808b60b2e51d84dc/LICENSE-APACHE).

Notices explicitly exclude ArtCraft branding from the code license and identify separately licensed fonts/assets. FilmCraft release builds can embed `craft-fonts`; that is an optional font asset input, not evidence of one shared engine crate. EffectCraft shares pinned **FilmCraft codec/interchange crates**; its time/text crates use a shared design but remain separate implementations. Inspect the exact dependency/asset graph if packaging a component. ## Recommended next decision gate

1. Select a pinned component and one bounded fixture; record license/dependency closure and exact adapter semantics. Start with interchange or scopes, where the boundary is inspectable.
2. Build the candidate in isolation and run its relevant upstream tests, then Ferrocut-specific timing/color/asset tests. Report skipped checks separately from passes.
3. Compare the adapted output in an independent receiving application or against an independent numeric/pixel oracle. Measure time, memory and information lost; keep original source projects and operation logs.
4. Adopt a component only after that evidence is reviewable. Consider a larger engine-provider experiment if isolated adapters outperform continuing native implementation; preserve the same agent discovery, edits, previews, verification and provenance contract either way.

No item in Ferrocut's parity ledger should be checked off solely because equivalent names or modules exist upstream. The present result is a source-backed shortlist for avoiding unnecessary duplication, with runtime and integration validation still outstanding.
