# Ferrocut implementation audit

Audit date: 2026-10-08. Baseline commit: `701b88f` (`main`). This describes the checkout before the new parity implementation lanes. It includes the pre-existing, uncommitted Rhai expression work; that work must be preserved. Current Adobe feature research is maintained separately in this directory. This document makes no assertion that an Adobe feature has been reproduced completely.

## Product and completion standard

Gordon's target is one professional editing, compositing and motion-graphics system designed for AI agents: Premiere-style editorial work and After Effects-style compositing in the same project. Familiar concepts, predictable commands, enough discoverable context and higher-quality finished videos are requirements. Feature implementation must preserve a single editable timing/project model; adding a standalone renderer or wrapper does not complete the corresponding workflow.

Track these evidence stages separately for every parity item:

1. **Source implemented:** relevant code exists, with its supported subset and limitations stated.
2. **Integrated:** ordinary timeline serialization, validation, compilation, edits, CLI and MCP can reach it.
3. **Tested:** meaningful tests exercise semantics and failures; record the actual command/result/date. Tests that skip are not passes of the skipped capability.
4. **Rendered:** a reproducible project exercises the full render/delivery path, including revisions and cache invalidation.
5. **Creatively reviewed:** someone has watched/listened to the output and recorded concrete findings. Numerical conformance checks are separate evidence.

The same distinction applies to dependencies: a cached crate or native library is available locally, not automatically linked, reachable, executed or verified as a Ferrocut feature.

### High-bit-depth and color-finishing gap

The compositor's linear ACEScg `RGBA16F` is useful internal precision. It does **not** mean the current project supports a high-bit-depth professional media pipeline:

- [`media/decode.rs`](../../crates/ferrocut-engine/src/media/decode.rs), around lines 158–197, converts incoming media to straight `RGBA8` (`Pixel::RGBA`). Higher-bit-depth input is quantized before compositing.
- [`compositor.rs`](../../crates/ferrocut-engine/src/compositor.rs), around lines 137–138, fixes source and output tags to `Camera Rec.709`; the upload/output kernels use those conversions. There is no per-source transform selected from ingest metadata.
- [`media/encode.rs`](../../crates/ferrocut-engine/src/media/encode.rs), around lines 67–99, uses `Pixel::BGRZ` and an eight-bit BGRA/BGR0 sink. The existing master does not preserve working-space float values or transparent alpha.
- [`media/probe.rs`](../../crates/ferrocut-engine/src/media/probe.rs) exposes streams, sizes/rates and audio properties, but no color-primaries/transfer/range/HDR metadata contract.
- Frames/data-window math contain pixel-aspect support, but project ingest/output settings do not provide a full anamorphic/conform contract. Do not check off format support based on that internal field alone.

Required dependent work is explicit input transforms/metadata → high-bit-depth decode/upload → configurable working/display/output transforms → float/10/12/16-bit and alpha-preserving output → metadata and cross-adapter validation. Native exposure and saturation can deliver useful finishing work now, but do not close this larger gap.

## First parallel implementation assignments and shared boundaries

All lanes use the existing `RenderNode`/`VideoEffect`, exact rational time, working-frame and error contracts. Root integrator owns edits to shared `Cargo.toml`/`Cargo.lock`, `lib.rs`, `generator.rs`, `timeline.rs`, `compile.rs`, `params.rs`, `edit.rs`, MCP schemas/guide and shared test fixtures. This avoids competing edits with the uncommitted expression work.

| Lane | Exclusive files | Boundary and scope |
|---|---|---|
| Native finishing | New `crates/ferrocut-engine/src/fx/finishing.rs`, `src/shaders/finishing.wgsl`, `tests/finishing.rs` | Export `pub fn all() -> Vec<Arc<dyn VideoEffect>>`. Implement native grading/keying with typed `ParamSpec` and independent GPU pipeline/worker resources. Root adds module and extends builtin registration. Current generic schemas/ops already handle numeric/vector/color/choice parameters; no new timeline model required. |
| Native typography | New `crates/ferrocut-engine/src/text.rs`, `tests/text.rs` | Export serializable `TextSpec`, validation/resource enumeration and `TextNode` with deterministic font/layout hash. | Native vector | New `crates/ferrocut-engine/src/vector.rs`, `tests/vector.rs` | Export serializable `VectorSpec`, validation and `VectorNode`; render editable geometry to premultiplied working-space pixels/coverage. Root wires generator variant and source-time parameters. Arbitrary mask references and stack attachment are a later coordinated integration step. |
| Integrator/reliability | Shared modules and matrix/demo artifacts | Verify registry discovery, parameter schemas, font/vector referenced assets under MCP root, nested-comp resource traversal, edits/undo/diff/cache behavior and a real master/delivery. Coordinate one heavy test/build run instead of parallel competing workspace builds. |

Finishing acceptance should include exposure as stops in a declared linear space, contrast pivot semantics, luminance-preserving saturation behavior, safe gamma controls, and a documented encoded-space chroma-distance/key threshold. Keyers must recompute premultiplied RGB when reducing alpha and test low-alpha/zero-alpha edges. An effect's output version participates in keys, and identity/disabled effects must preserve existing behavior.

The current generic effect parameter value contract supports scalar/vector/bool/choice values, not arbitrary file assets, free text or curve arrays. OCIO LUT files, font files and OFX plugin resources need explicit resource/hash/validation interfaces; do not smuggle paths into numeric parameters or bypass MCP source checks. Generated type-specific schemas must use the same metadata as engine validation to keep the interface familiar and truthful.
