# After Effects capability inventory

Research snapshot: **2026-10-08**. Scope: the professional capabilities documented for Adobe After Effects, as a reference for Ferrocut's combined editing/compositing system for agents. This file is a research baseline, not a declaration of implemented Ferrocut features.

Adobe's current production documentation identifies **After Effects 26.5, September 2026**. The release-notes page was updated September 9; the canonical English what's-new page was updated September 18. Confidence is high for that documented production version. The separate beta overview was updated October 7; beta items are excluded from the stable baseline. No installed Adobe build was operated for this research. [Release notes](https://helpx.adobe.com/after-effects/desktop/what-s-new/release-notes-after-effects.html), [what's new](https://helpx.adobe.com/after-effects/desktop/what-s-new/whats-new.html), [beta overview](https://helpx.adobe.com/after-effects/desktop/what-s-new/after-effects-beta.html).

There are **229 capability rows**, including **219 stable-baseline rows** and **10 beta watchlist rows**, with **124 distinct official source pages** linked directly from rows. IDs are stable identifiers: preserve existing IDs when revising descriptions, and append new IDs instead of renumbering after deletions.

## How to read and verify this inventory

A row describes a meaningful capability, sometimes a closely related family of controls. It does not certify every menu item, effect parameter, codec variant, platform, or plugin version. “Native” identifies a built-in creative capability rather than proving Adobe's internal implementation or promising Ferrocut's implementation architecture. The table deliberately separates third-party bundles, other applications, services, and interface concepts.

| Class | Meaning | Rows |
| --- | --- | ---: |
| native_core | Production creative/project/render capability built into After Effects. | 190 |
| bundled | Adobe-distributed third-party component or effect collection; licensing/runtime compatibility matters. | 6 |
| ecosystem | Separate application, plugin ecosystem, encoder, or hardware integration. | 10 |
| cloud | Account/service-dependent assets, collaboration, or review. | 3 |
| ui_equivalent | Production interface capability needing an inspectable agent command/query rather than literal panel replication. | 10 |
| beta_native | Documented beta creative capability, outside stable parity. | 6 |
| beta_cloud | Documented beta service/assistant capability, outside stable parity. | 2 |
| beta_ui | Documented beta interaction capability, outside stable parity. | 2 |

Acceptance criteria below are **proposed Ferrocut checks**, not tests already run or proof of Adobe equivalence. To close a row, an agent must be able to discover the operation, inspect its schema/units, perform and revise it, save/reopen the result where relevant, and obtain useful errors. Rendering capabilities need output evidence at meaningful intermediate times, including alpha/color/timing checks and representative footage. A type, placeholder parameter, unconnected render node, or one synthetic happy-path frame does not establish professional parity.

Agent familiarity should preserve useful concepts—composition, footage, layer, source time, keyframe, selector, matte, camera, effect stack, and render queue—with concise examples and explicit semantics. A screen-only menu or undocumented API is not an equivalent usable workflow.

## Coverage and research limits

Reviewed guide areas include projects/compositions; importing, interpretation, media management and metadata; color/ICC/OCIO/HDR; layers, parenting and blending; keyframes, graph editing, expressions and data; text and variable fonts; vectors, SVG, paths and paint; masks, mattes, roto and fill; keying, tracking and stabilization; cameras, lights and native 3D; the effect-category reference; audio; Motion Graphics templates; preview/cache/performance; export/headless rendering; scripting, plugins, interchange and collaboration. The [current user-guide navigation](https://helpx.adobe.com/after-effects/desktop.html) was used to check breadth, alongside detailed pages below.

This is capability-level coverage, not a claim that every Adobe control is enumerated. The effect rows name significant mechanisms and collections; they do not individually specify hundreds of effect controls. Historical/obsolete effects, keyboard shortcut variants, workspace cosmetics, tutorials, every codec/OS matrix entry, and every third-party product are not implementation commitments here. Accessibility, localization, SDK ABI compatibility, Adobe project-format compatibility, legal/licensing feasibility, and Adobe's unpublished algorithms need separate specifications.

Some guide pages lag release status or contradict newer pages. Current release/beta pages and specific current feature pages take precedence over stale general prose. Examples: track mattes no longer require adjacent layers; some generic pages retain beta labels for shipped features; the plugin directory retains old “latest version” wording. A listing there does not certify plugin compatibility with 26.5. The canonical paragraph page failed to resolve during retrieval; its official Adobe MENA-English variant is cited instead.

## Dependencies and implementation cautions

- **Foundational order:** accurate time/units and media interpretation; transparent high-depth frame representation; color-managed compositing; persistent composition/property graph; deterministic evaluation; then vectors/text/mattes, temporal effects, vision tools, native 3D, and delivery. Cross-layer references and temporal sampling require dependency and cycle rules.
- **Vectors and typography:** coverage must include antialiasing, contour holes, joins/caps, gradient alpha, transforms, font availability/shaping, and animation. Native vector primitives alone do not close the complete shape-operator, editable typography, or SVG-import families.
- **Vision and temporal processing:** tracking, stabilization, roto, keying, optical flow, and removal need representative occlusion, hair, motion blur, rolling shutter, and changing illumination fixtures. Parameter/API presence cannot establish their quality.
- **Color and rendering:** bit depth, premultiplication, scene/display transforms, HDR metadata, motion sampling, output codec behavior, and cache invalidation must be tested together. Preview rendering and final movie encoding are separate operations.
- **Native 3D:** renderer feature matrices and hardware requirements differ. Imported cameras/lights are extracted copies; mesh displacement increases geometric cost; emissive materials do not necessarily cast light. SBSAR on models/meshes is stable, while SBSAR on 3D text/shapes and live layer materials remain beta in this snapshot.
- **Interchange and external systems:** Dynamic Link depends on matching Adobe versions; PRPROJ export discards many AE constructs; plugin/Cineware/Cycore/Keylight/Mocha compatibility and licenses need explicit checks. Cloud features require account/plan/access handling. Equivalent creative behavior does not imply Adobe binary or file-format compatibility.
- **Completion evidence:** keep this source inventory separate from implementation status. Link each verified row to actual schema/API support, agent example, rendered artifact or meaningful test, and known limits. A stable count of passed unit tests is not a percentage of Adobe parity.
